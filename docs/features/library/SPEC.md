# Library

## Summary

One list of everything Sessions produced: the Markdown and HTML reports they wrote, the Artifacts they published on claude.ai and the Backyard Shares they uploaded. Each Output links back to the Session that made it, so it can be opened, copied, or regenerated by resuming that Session. The Library is a third tab in the right sidebar, beside History and Work, and it reads a new `tb-session outputs` command ([contract](../../contracts/tb-session-outputs.md)): tb-session mines the Transcripts, Lookout only renders.

## Problem

A Session writes a report into `output/` or a scratchpad, publishes an Artifact, or uploads a Share, and a day later finding it again means remembering a path or a URL, or searching History for the Session and reading its chat. Artifacts have no list outside claude.ai's gallery, which doesn't say which Session published them. Scratchpad files are gone within a week, and by then the Artifact made from them is the only copy.

Measured over the last 30 days (2026-10-23): 143 Sessions wrote at least one document, 199 Artifact publishes went to 25 URLs, and 15 Shares were uploaded; a third of the `output/` documents were written by Subagents, whose Transcripts nothing lists today.

## Non-goals

- Codex and Pi sources, Claude Docs, gists, PR bodies and comments, Slack canvases, screenshots: PRs are WORK's items (175 creates and 237 body edits in 30 days would bury the documents); Claude Docs and Codex come in slice 2 (Later); the rest until one is missed.
- Repo documents: a tracked `SPEC.md`, `knowledge/` or `docs/` file has a home, a PR and reviewers; its published `SPEC.html` Artifact is in anyway.
- Code, `.txt`, `.json`, `.csv` and `.jsonl` files: in 30 days they were scratch (763 `.txt` writes, 124 `.json`). Widening the extension list is a one-line change in tb-session (contract C4).
- Content search, an in-app preview, moved-file (`cp`/`mv`) and heredoc tracking: slice 3.
- Backyard reconciliation (state, expiry, views, deletion) and Artifact reconciliation with claude.ai: slice 2 and 3; in slice 1 a Share's `visibility`, `state` and `expires_at` are what its upload printed.
- Deleting, renaming, tagging or moving Outputs; uploading, publishing or regenerating anything from Lookout. Resuming the Session is how an Output is regenerated.
- Reading a file's contents in Lookout or in tb-session to index, title, preview or search it; the Open route streams a listed file to a tab as it is. A file's title comes from the Write's `content` in the Transcript or its basename.
- Serving a page's sibling files (`./chart.js`, `./style.css`): the route serves the listed file alone (Known gaps).
- Dropping gone Outputs from the index: history is never dropped automatically (tb-session's `transcript_missing` rule); the Session link of a gone report is how you get it back.
- Other Hosts.

## Technical approach

### Source ([0005](../../decisions/0005-building-blocks-live-outside-lookout.md), [contract](../../contracts/tb-session-outputs.md))

- **Command:** `tb-session outputs --all-projects --json` with `--kind`, `--type`, `--project`, `--q`, `--headless`, `--limit` and `--page` (contract C1). The fields, the include rule and its `ext → type` table, the fold, the change keys, the budget and the boundary are the contract's (C2 to C10); this section keeps what Lookout does with them and why.
- **Flags from the filters** (LIB-2.3): `--kind` is `share` for Share, `artifact` for Pages, plus `file` when any of Pages, PDF, Markdown or Image is on; `--type` is `html` for Pages and the other three chips' names. `--type` narrows file rows only, so Pages is `--kind file,artifact --type html` and nothing else can say "HTML files and Artifacts" on one page. `--project` is the repo select's exact `project_path`; `--headless` is History's toggle.
- **Subagents:** a Subagent's Transcript lives at `<project>/<session-id>/subagents/agent-*.jsonl`, so crediting the parent is by path. tb-session's Claude scanner reads only `<project>/*.jsonl` today, so the outputs pass also reads `subagents/`, each file with its own change key (contract C7). 478 of about 1,500 document writes in 30 days were in Subagents, from 20 parent Sessions.
- **The fold** (contract C5): a `file` item whose path is an Artifact's `source_path` is not a row of its own; the Artifact's row carries it as `source`, tb-session's doing, so a page of 50 is 50 rows and `total_results` is exact. Lookout shows the file's path and its last edit in the expanded row, says the file is newer than the published version when `source.updated_at` is after the Artifact's `updated_at`, stats `source.path` for the "Open file" button, and never hides the Artifact's row for a gone source. 95 of 182 publishes had their file Written or Edited in the same Session; the rest came from a heredoc, an earlier Session or a Subagent, and have `source_path` without `source`.
- **Artifacts have no list but the Transcripts:** the Artifact tool's `list` works only from inside a Session, gives no Session or creation time, and there's no CLI or public API (the `claude` binary talks to an MCP endpoint behind claude.ai's session auth). The Transcripts give `artifact_id`, `url`, `title`, `version`, `seq`, `updated`, `path` and every publish's time. They can't give a title changed on the web, a deletion, or an Artifact published from Claude Desktop (Known gaps).
- **Codex** (slice 2): a rollout's `patch_apply_end` event carries `changes: {<path>: {type, content | move_path, unified_diff}}`, and `exec_command` calls carry `cmd`; 140 file changes in 120 days, 7 of them documents, 5 Share uploads. The source trait makes it one more `parse` implementation.

### Paging and existence (Lookout's server, LIB-2.1, LIB-2.9)

- **Filling a page:** for one tab page the server reads up to five tb-session pages of 50 (a warm call is 0.19 s, a stat batch milliseconds, so under a second in all), stats each, drops gone file rows while "Hide gone" is on, and answers the rows kept with `nextPage` (the next tb-session page) and `hasMore`; no total, since the gone ratio can't be known without the stat. The repo filter is tb-session's (`--project`), so it never shortens a page.
- **The stat:** VIEW-1.18's batched check (`server/files.ts`, `checkPaths`: at most 100 paths, 2 s for the batch, `stat` only, nothing opened, no command), over the file rows' paths and the Artifact rows' `source.path`s; a page of 50 holds at most 100 of them, one batch. The answer is `exists` on Lookout's row, never stored: a file can come back (a Session rewrote it) or go between two refreshes.
- Evidence for "Hide gone" on by default: scratchpad documents last touched 0–3 days ago all existed (120 of 120), 4–7 days 28 of 60, older than 8 days 0 of 83; `output/` 45 of 45. A scratchpad file is the thing to open while it lives, and gone within a week, when the Artifact or Share made from it is the lasting item (32 of 52 Artifact source files were scratchpad files). Deep history is therefore mostly gone files, which is why the server fills a page rather than passing short ones to the tab.
- tb-session reports no existence, by its boundary (contract C9): `exists` would be a read of files on disk at answer time, the thing the boundary keeps out, and Lookout already has the check.
- **The repo select** is built from every `project_path` the server has seen in any `outputs` answer since it started (kept beside the route's allowlist) plus the chosen one: `outputs` has no facet counts, and adding one is more tb-session surface than the select is worth.

### Liveness and the Session chips (LIB-2.2, LIB-3.5)

- A row is live when any of its `sessions[]` ids is in the Session list Lookout already has (HIST-3.2's rule); that chip is "Open", which selects it.
- The chip's title, Harness, `project_path`, `headless` and `transcript_missing` come from the `sessions[]` entry (contract C2), so no `show` is needed on expand; Lookout's `withBlock` then applies as in History.
- Resume and Show go through History's resume route (`{sessionId, harness}`; the server re-reads the Session with `tb-session show`, so the directory never comes from the browser), with its answers `started`, `live` and `blocked` and its "Starting…" row (HIST-3.1, HIST Technical approach, Resume request). Nothing new is spawned here.
- A Session whose Transcript was deleted is `transcript_missing` in tb-session and still answers `show`: its chip is "Show" (HIST-3.3). One removed by `index --prune` is `pruned` in the entry and `session_not_found` in `show`, so its chip is text (LIB-2.6).

### Opening (LIB-3.3, LIB-3.4)

- A `.md` that exists opens in VS Code through `vscode://file/<absolute path>` (VIEW-1.17), where its source is what you'd edit. Everything else a browser renders natively opens in a new tab from a read-only route: `.html` and `.htm` as `text/html`, `.pdf` as `application/pdf`, images with their type (an SVG can carry scripts, so it gets the same sandbox). Chrome won't open `file://` from an `http` page, so a route is needed.
- The route answers with `Content-Security-Policy: sandbox allow-scripts allow-popups allow-popups-to-escape-sandbox` and `X-Content-Type-Options: nosniff` on every answer, errors included. `allow-scripts`: charts work; storage APIs such as `localStorage` don't, accepted. No `allow-same-origin`: the page is an opaque origin, its `fetch` to Lookout carries `Origin: null`, which `server/security.ts` refuses (403). `allow-popups` with `allow-popups-to-escape-sandbox`: links in a report (PRs, Backyard, Grafana) open as ordinary tabs of their own origin, not sandboxed and half-broken; a popup aimed at Lookout's origin is a plain GET, carries no token, can't call a mutation, and the page can't read it back (cross-origin).
- **The allowlist:** every file path any `outputs` answer listed for this server since it started (file rows' paths and `source.path`s), bounded at 10,000 with the oldest out, compared as the exact normalized string: nothing is joined to a root, so no traversal is possible. The leaf must be a regular file by `lstat` (no symlink at the leaf; a symlinked parent such as `/private/tmp` is fine) and its extension one the route serves. The route reads the file as it is, serves nothing else (no sibling files, Known gaps) and runs no command.
- An Artifact or Share opens its URL in a new tab with no referrer (VIEW-1.12). Lookout never fetches the URL.
- Copy link uses the clipboard as VIEW-1.14 does; the text is the URL, or the file's absolute path.

### Freshness (LIB-2.7, LIB-2.8)

- The tab reads `outputs` when opened, within 10 s after Fleet's list changes (the moment an Output is likely new: a Session ended, a Subagent finished; Lookout reads Fleet's list every 2 s), and every 60 s while the tab is visible. A warm call is cheap; a call that re-parses a changed live Transcript costs that parse (1.57 s for 30 MB), which is why 30 s was rejected and why the contract keys Subagent files separately (C7).
- A refresh re-reads page 1 in full (0.19 s warm), replaces it, and drops from later pages any key page 1 now holds; a `--after` delta would have to be merged into a paged list (an Edit moves a row from page 3 to page 1), so it isn't used.
- The 20 s timeout, `LOOKOUT_TB_SESSION_BIN`, `PATH`, then `~/.local/bin` apply as for History, except the first call after an upgrade: a schema bump re-parses every Transcript on first use (contract C10, within 60 s here), and that same call hits History and Work, so the Library waits 60 s with "Indexing Transcripts…" rather than answering a 504 on upgrade day; past 60 s the Alert names `tb-session index --all-projects`.
- A tb-session without `outputs` fails the call with clap's usage error on stderr, `error: unrecognized subcommand 'outputs'`, exit 2 (checked on 0.3.2), which Lookout shows as the install hint. `server/history.ts` matches only `unexpected argument '--…'` for its `legacy` flag, so the Library matches its own line and keeps its own flag.
- The list keeps its order while a row is expanded or the pointer rests on it (SIDE-3.4); pending moves apply once both end.

Lookout is built against it through its fake tb-session first; the pin in `e2e/pins.json` (0.3.0 today; the installed tb-session is 0.3.2), the Worlds' `logged` wrapper and TOOLS's row move to the release once it exists.

### Known gaps

- **Moved files:** not tracked in slice 1; the old path goes gone, and the new one appears only once a Session Writes or Edits it. `cp`/`mv` into `output/` happened 78 times in 30 days (slice 3).
- **Files written by a shell heredoc:** not Outputs in slice 1 (218 such Bash calls in 30 days, mostly review notes in `/tmp`); an Edit of one later makes it an item (slice 3 for the obvious forms). An Artifact published from such a file has `source_path` but no folded `source`.
- **A page's sibling files:** a report that references `./chart.js` or `./style.css` breaks in the route, which serves the listed file alone; brand Artifacts inline everything, and multi-file pages are what the Artifact tool's `files` is for.
- **Artifacts changed on the web:** a title changed, an Artifact deleted, or one published from Claude Desktop or the web isn't seen; the row keeps the last publish's `title` and `version`.
- **Shares deleted or expired:** not seen until the Backyard reconcile (slice 2); the row shows what the upload printed.
- **Title of a file:** from the first Markdown heading or `<title>` in the Write's `content`, or the basename; an Edit never changes it.
- **A folded Markdown source:** an Artifact published from a `.md` (a skill may ask for one) folds that file under the Artifact, so the Markdown chip alone doesn't list it; Pages does.

### Key decisions

- **Mine the Transcripts, don't scan the disk**: every `Write`, Artifact publish and Share upload is in them with its path or URL and its Session; a disk scan has no Session link, no Artifacts or Shares, and the scratchpads are gone within a week.
- **The index lives in tb-session, not a standalone `tb-outputs` crate** (Dario, 2026-10-23): a standalone would parse the same bytes for the same reason (two parsers kept in step, or tb-session's parsers as an unversioned library, which no crate in the workspace does today), copy or join every Session fact the Library shows (titles, renames, project, headless, missing Transcript, resumable), split WORK's refs index (Gap 2, the same walk over tool blocks) and add a pin, a wrapper, a fake and a version for Lookout; the costs it would spare tb-session are measured and small (a full rebuild is 8 s, the tables are kilobytes beside a 113–237 MB index). Fleet reads tails and never tool results, and Lookout's own server is against 0005.
- **tb-session's boundary is written down, with one named exception** (correction to the draft, Dario, 2026-10-23): "facts from Transcripts; the git-owned check at index time is the one other input; nothing from the network, nothing from files at answer time". The draft had tb-session stat files for `exists` and run `git` for the include rule, both reads outside the Transcripts; the stat moves to Lookout, which already has the batched check (VIEW-1.18), and the git check stays because without it every repo file an agent writes would be indexed, and it runs once per directory at index time, never when answering.
- **The tb-session contract is a file, not criteria** (grill, 2026-10-23): `pnpm req-check` reads Vitest's and Playwright's listings, never Rust tests in another repo, and a Lookout test named after a tb-session point would prove the fake, not tb-session; HIST and WORK hold their Building-block gaps under Technical approach too. `docs/contracts/tb-session-outputs.md` is what the cli-toolbox PR implements and tests against.
- **One row of Type chips, Pages = HTML files + Artifacts** (Dario, 2026-10-23, changed from the grill's six): what Dario narrows to is "the pages", and an HTML file and an Artifact are the same thing to open, a page in a browser tab, often the same page before and after publishing; one chip for both means the fold (below) never has to decide which chip a row belongs to. "Pages" over "HTML / Artifact": one word that names the use, fits five chips at 280 px, and the hover spells out "HTML files and Artifacts". Multi-select with ⌥-click for "only this", remembered, so the daily view is a one-time setup, not a preset; tb-session owns `type` and `--type` because it already owns the extension rule, and a flag keeps paging exact where filtering after the fact would make pages short.
- **An Artifact and its source file are one row** (Dario, 2026-10-23, changed from the grill's "don't fold"): one page, one row. The grill's reasons against folding were about which chip a folded row belongs to; with HTML files and Artifacts on one chip that question is gone. The fold is tb-session's so paging stays exact; the file is reachable through the Artifact's row (its path, "Open file", "newer than published"), nests under two Artifacts when it's the source of both, and its going never hides the Artifact.
- **The server fills a page; the repo filter is tb-session's `--project`** (grill, 2026-10-23): deep history is mostly gone files (0 of 83 scratchpad documents older than 8 days), so passing tb-session's short pages to the tab would make the Library a "Load more" clicker; five tb-session pages per tab page cost under a second, and `--project` keeps `total_results` true for a repo. "Hide gone" stays the server's, since the gone ratio needs the stat (contract C9).
- **The first call after an upgrade waits 60 s with "Indexing Transcripts…"** (grill, 2026-10-23): a schema bump re-parses everything once (6–8 s today, up to 3× with Subagent files) and that call hits History and Work too, so a 504 on upgrade day is the worst outcome; a longer wait with an honest label costs nothing on every other day, and `tb-session index --all-projects` is the fallback the Alert names.
- **Only `.md` opens in VS Code; `.html`, `.htm`, `.pdf` and images open from the route** (grill, 2026-10-23): VS Code has no PDF viewer and would show an `.html` as source; Chrome renders all four natively, so one route, one allowlist, one sandbox policy, one test.
- **The route's sandbox is `allow-scripts allow-popups allow-popups-to-escape-sandbox`, never `allow-same-origin`** (grill, 2026-10-23; the draft had `allow-scripts` alone): without the popup flags every link in a report is dead, and what the escape protects, Lookout's origin, is already guarded by the token on every mutation and the Origin check on every fetch. Sibling files stay unserved: a wider surface for a rare case.
- **`O`, `C` and `S` on the selected row** (grill, 2026-10-23): Enter reaches the first button only, and row buttons aren't focusable (DS-7.2), so without keys a keyboard user couldn't copy a link or reach a Session; WORK solved the same gap with `O`, `R` and `S` (WORK-6.4), and Library reuses its rule and words.
- **Sessions are chips as WORK-4.10, not one Session button** (grill, 2026-10-23): 20 of 540 documents were touched by more than one Session, and one button can't say which; the component exists with its order, cap and accessible names specified and tested.
- **A pruned Session gets no button** (grill, 2026-10-23): "Show" reads `tb-session show`, which answers `session_not_found` for a Session `index --prune` removed; a `transcript_missing` one still answers, so it keeps "Show".
- **Enter on a gone row does nothing** (grill, 2026-10-23): with Open gone the "first button" would be Copy link, and Enter copying a path is a surprise; `S` and the chip are one key or click away.
- **Refresh on open, on Fleet's list changing and every 60 s while visible, not every 30 s** (grill, 2026-10-23): a refresh re-parses a changed live Transcript in full (1.57 s for 30 MB, the largest here is 118 MB), so 30 s while open was a parse of the biggest live Session twice a minute; Fleet's list changing is the moment an Output is likely new, and per-file change keys (contract C7) are what make the 2.2× Subagent bytes affordable.
- **The `(e2e)` list and the World's needs are written now** (grill, 2026-10-23): it makes the retag a mechanical step when the pin lands and tells the tb-session PR which fixtures to ship.
- **Repo documents are out by the git rule** (Dario, 2026-10-23): a tracked `SPEC.md` or `knowledge/` file has a home, a PR and reviewers, and the `SPEC.html` Artifact is in anyway; reversible later with a per-path allowlist.
- **Scratchpad files are in while they exist, hidden once gone, "Hide gone" on by default** (Dario, 2026-10-23): 0 of 83 scratchpad documents older than 8 days still existed, and while they live they're the thing to open.
- **Kinds in slice 1 are file, Artifact and Share; Claude Docs in slice 2; PR bodies and gists out** (Dario, 2026-10-23): 4 Claude Doc creates in 30 days, 0 gists ever, and a PR is WORK's item.
- **Extensions: `md, html, htm, pdf` and images; `txt`, `json`, `csv` out** (Dario, 2026-10-23): 763 `.txt` and 124 `.json` writes in 30 days were scratch, and widening the list is one line.
- **Subagent Outputs are credited to the parent Session** (Dario, 2026-10-23), though tb-session must start reading `subagents/`: 478 of about 1,500 document writes happened in Subagents; without them a third of `output/` is missing.
- **Liveness is checked at read time, never stored as truth, and split by input** (Dario, 2026-10-23, amended by the correction above): files are Lookout's stat per page; Backyard's state is Lookout's join with `tb-backyard share list` (slice 2), since tb-session has no network and no PAT and Lookout already calls tb-pr with the same rules; nothing checks an Artifact.
- **A third right-sidebar tab with `L`, not a section inside History** (Dario, 2026-10-23): the Library is a list of items, not of Sessions, with its own filters; History's list stays a list of Sessions. HIST's Non-goals left the room ("PORTS can become one later").
- **Search in slice 1 is over title, path and URL, not content** (Dario, 2026-10-23): History already finds the Session that produced "the report about X", and content FTS needs a size cap and a Transcript-only source (slice 3).
- **Headless Sessions' Outputs follow History's headless toggle, shown in Library too** (Dario, 2026-10-23): about 60 of the last 300 Sessions were headless eval runs, their reports are real Outputs, and the toggle already exists; showing it in the filter row is what lets the Library explain itself.
- **One item per key, with versions and "touched by", not a row per event**: 199 publishes went to 25 URLs, 46 of 540 document paths had 5+ edits and 20 were touched by more than one Session; a row per edit would be noise.
- **Gone items stay in the index**: tb-session never drops history (`transcript_missing` is the same pattern); the Session link of a gone report is how it's regenerated.
- **A click selects and expands; a button acts** (HIST-3.5, WORK-1.12): a stray click must never open a tab or resume a Session.
- **`index --prune` keeps a pruned Session's Outputs** (Dario, 2026-10-23): tb-session never drops history on its own; the item's `sessions` keeps the id, marked `pruned`.
- **Harness homes are only the roots tb-session's scanner already knows** (Dario, 2026-10-23): `CLAUDE_CONFIG_DIR` and `CODEX_HOME` set in a Session's environment aren't in the Transcript, so they aren't considered.
- **A Share uploaded without `--json` is anchored on its URL alone** (Dario, 2026-10-23): `title` and `visibility` are parsed from the printed text when it parses and left empty when it doesn't, so a change in tb-backyard's text costs fields, never the item.
