# Library

## Summary

One list of everything Sessions produced: the Markdown and HTML reports they wrote, the Artifacts they published on claude.ai and the Backyard Shares they uploaded. Each Output links back to the Session that made it, so it can be opened, copied, or regenerated by resuming that Session. The Library is a third tab in the right sidebar, beside History and Work, and it reads a new `tb-session outputs` command: tb-session mines the Transcripts, Lookout only renders.

## Problem

A Session writes a report into `output/` or a scratchpad, publishes an Artifact, or uploads a Share, and a day later finding it again means remembering a path or a URL, or searching History for the Session and reading its chat. Artifacts have no list outside claude.ai's gallery, which doesn't say which Session published them. Scratchpad files are gone within a week, and by then the Artifact made from them is the only copy.

Measured over the last 30 days (2026-10-23): 143 Sessions wrote at least one document, 199 Artifact publishes went to 25 URLs, and 15 Shares were uploaded; a third of the `output/` documents were written by Subagents, whose Transcripts nothing lists today.

## Requirements

Slice 1 is what the criteria cover; slices 2 and 3 are under Later. Building blocks: tb-session with an `outputs` command (LIB-4, a cli-toolbox PR that lands first, Dependencies), and Fleet for live Sessions, as today. Lookout shows the Library tab with any tb-session; one without `outputs` shows the install hint, as History does for 0.2.

### LIB-4 Dependency: `tb-session outputs`

The contract Lookout builds against, built in cli-toolbox by a separate PR (Dependencies, Gap 1), like HIST's Codex source and WORK's tb-pr 0.4.0. Verified in cli-toolbox's own tests and through Lookout's fake tb-session.

- [ ] LIB-4.1 `tb-session outputs --json` answers `{total_results, page, results: [...]}` with the fields under Technical approach, add-only; `--kind`, `--session <id> --harness <h>`, `--after`, `--before`, `--q`, `--headless`, `--limit`, `--page` and `--all-projects` work as `list`'s do. (test)
- [ ] LIB-4.2 An Output comes from the Claude Code source's `Write`, `Edit`, successful `Artifact` publishes and `Bash` calls that ran `tb-backyard share upload` (the URL is the only anchor: `title` and `visibility` are parsed from the printed text when it parses and left empty when it doesn't), in the parent Transcript and in `<session>/subagents/*.jsonl`, credited to the parent; the parent's change key covers its Subagent files, so a Subagent's write re-indexes the parent. (test)
- [ ] LIB-4.3 A file is an Output only when its extension is a document's (`md, html, htm, pdf, png, jpg, jpeg, gif, svg, webp`) and its path is neither git-owned (inside a work tree and not ignored) nor under a Harness home, which is only a root tb-session's scanner already knows (`~/.claude`, `~/.codex`, `~/.pi`); `CLAUDE_CONFIG_DIR` and `CODEX_HOME` set in a Session's environment aren't considered. The git answer is found at index time, once per distinct directory and cached, never at answer time: an `outputs` call runs no `git`. (test)
- [ ] LIB-4.4 Repeated events on one key make one item: `created_at` from the first, `updated_at` from the last, `events` counted, `sessions` listing each Session once with its last touch; a refused Artifact publish (no `artifact_id`) is no event. (test)
- [ ] LIB-4.5 Rows are never dropped when a file or a Transcript goes, and tb-session says nothing about whether a file exists: `outputs` reads no file but the Transcripts and stats none (LIB-2.9 is Lookout's). `index --prune` removes a pruned Session's row but keeps its Outputs, and an item's `sessions` keeps that id; Lookout shows that Session's button as "Show" (LIB-3.5). (test)
- [ ] LIB-4.6 A full re-index of this machine's Transcripts with outputs on, Subagent Transcripts included, stays within 3× of today's 6–8 s (they add 2.2× the bytes); a warm `outputs --json` call with nothing changed answers within 0.3 s, and one with a single changed 30 MB live Transcript within 2 s, as `list` does today (measured 0.19 s and 1.57 s). The outputs tables add less than 1 MB per 1,000 Sessions, and `search` and `list` timings are unchanged. (manual)
- [ ] LIB-4.7 tb-session's README and SKILL.md state its boundary: it indexes facts from Transcripts, with one named exception, the git-owned check of LIB-4.3 at index time; it reads nothing from the network and nothing from files at answer time, so a reconciliation with Backyard or claude.ai, or an existence or content check of files on disk, is never added to it (it's tb-backyard's, a Session's, Lookout's or a separate tool's). A schema bump to v4 migrates an older index without dropping rows, as the v3 migration does, and re-parses on first use. (test)

## Non-goals

- Codex and Pi sources, Claude Docs, gists, PR bodies and comments, Slack canvases, screenshots: PRs are WORK's items (175 creates and 237 body edits in 30 days would bury the documents); Claude Docs and Codex come in slice 2 (Later); the rest until one is missed.
- Repo documents: a tracked `SPEC.md`, `knowledge/` or `docs/` file has a home, a PR and reviewers; its published `SPEC.html` Artifact is in anyway.
- Code, `.txt`, `.json`, `.csv` and `.jsonl` files: in 30 days they were scratch (763 `.txt` writes, 124 `.json`). Widening the extension list is a one-line change in tb-session.
- Content search, an in-app preview, moved-file (`cp`/`mv`) and heredoc tracking: slice 3.
- Backyard reconciliation (state, expiry, views, deletion) and Artifact reconciliation with claude.ai: slice 2 and 3; in slice 1 a Share's `visibility`, `state` and `expires_at` are what its upload printed.
- Deleting, renaming, tagging or moving Outputs; uploading, publishing or regenerating anything from Lookout. Resuming the Session is how an Output is regenerated.
- Reading a file's contents in Lookout or in tb-session, for a title, a preview or search. A file's title comes from the Write's `content` in the Transcript or its basename.
- Dropping gone Outputs from the index: history is never dropped automatically (tb-session's `transcript_missing` rule); the Session link of a gone report is how you get it back.
- Other Hosts.

## Technical approach

### Source ([0005](../../decisions/0005-building-blocks-live-outside-lookout.md))

- **Command:** `tb-session outputs [--all-projects] [--kind file,artifact,share] [--session <id> --harness <h>] [--after 7d] [--before …] [--q <text>] [--headless include|exclude|only] [--limit 50] [--page 1] --json` (Gap 1). Every field is add-only:

  ```
  { total_results, page, results: [ {
      kind, key,                 // file: absolute path; artifact: url; share: token
      title,                     // artifact and share from the result; file from the first heading
                                 // in the Write's content, else the basename
      url, path,                 // whichever applies; artifact and share also carry source_path
      harness, session_id,       // the parent Session that first produced it
      project_path, git_branch, headless,
      created_at, updated_at, events,              // first and last event, number of writes/edits/publishes
      sessions: [{harness, session_id, last_at}],  // every Session that touched it, newest first
      version, seq,              // artifact: the last publish's
      visibility, state, expires_at                // share: from the upload's output, not reconciled
  } ] }
  ```

  There is no `exists`: tb-session stats nothing (LIB-4.5); Lookout does (Existence, below).
- **Tables:** `outputs (harness, session_id, kind, key, title, source_path, project_path, created_at, updated_at, events, version, seq, visibility, state, expires_at, PRIMARY KEY (kind, key))` and `output_events (kind, key, harness, session_id, subagent, event, ts, version)`, filled in the same incremental pass as the messages (`ensure_fresh`, change key = Transcript mtime + size, widened to cover `subagents/`), inside the same per-Session transaction and error handling, so a bad Transcript is skipped with a warning as today. `--q` is a `LIKE` over title, key and source_path. A schema bump to v4 re-parses everything once, as the v3 migration did (6–8 s here).
- **What makes an Output** (LIB-4.2, LIB-4.3):

  | Event in the Transcript | Kind | Key | Rule |
  |---|---|---|---|
  | `Write` of a file (`toolUseResult.filePath`) | `file` | absolute path | document extension; not git-owned; not under a Harness home (only the roots the scanner knows: `~/.claude`, `~/.codex`, `~/.pi`) |
  | `Edit` of a qualifying file | `file` | absolute path | same rule; updates `updated_at`, adds the Session to `sessions`; creates the item if it isn't known (the file was made by a heredoc, say) |
  | `Artifact` publish whose `toolUseResult` has `artifact_id` and `url`, not `asset: true` | `artifact` | `url` | every successful publish; an update to the same URL is a version of one item (199 publishes went to 25 URLs in 30 days) |
  | `Bash` whose command runs `tb-backyard share upload`, with a `backyard.productive.io/s/<token>` URL in its stdout | `share` | token | the URL is the anchor; with `--json` the stdout is the full `ShareResponse`, read for `title`, `visibility`, `state`, `expires_at`; without it `title` and `visibility` are parsed from the printed text when it parses, else left empty |

  - **Git-owned** means inside a git work tree and not ignored (`git check-ignore`). `~/Projects/work/output/` is ignored, so it's in; a scratchpad under `/private/tmp/claude-<uid>/…` has no repo, so it's in; tracked specs and knowledge files are out. It's the one thing tb-session reads outside the Transcripts, and only at index time: once per distinct directory, cached (work-tree root and the ignore answer per directory; `git.rs` already shells out to `git worktree list`). Without it, every repo file an agent writes would be an Output.
  - Why the rule is mechanical: it's decided from the path alone, so the index never reads the file or guesses intent, and it matches what the Library is for, things with no other home.
  - **Subagents:** a Subagent's Transcript lives at `<project>/<session-id>/subagents/agent-*.jsonl`, so crediting the parent is by path. tb-session's Claude scanner reads only `<project>/*.jsonl` today, so the outputs pass also reads `subagents/`, and the parent's change key covers those files (a Subagent writing a report doesn't change the parent's mtime or size). 478 of about 1,500 document writes in 30 days were in Subagents, from 20 parent Sessions.
  - **Tying an Artifact to its local file:** the publish's `file_path` is its `source_path`; the `file` item with that path, if any, is folded under the Artifact's row in the UI (95 of 182 publishes had that file Written or Edited in the same Session; the rest came from a heredoc, an earlier Session or a Subagent).
  - A refused publish (`is_error`, no `artifact_id`; 17 of 200 in 30 days), an asset upload and a `files` map aren't events.
- **Artifacts have no list but the Transcripts:** the Artifact tool's `list` works only from inside a Session, gives no Session or creation time, and there's no CLI or public API (the `claude` binary talks to an MCP endpoint behind claude.ai's session auth). The Transcripts give `artifact_id`, `url`, `title`, `version`, `seq`, `updated`, `path` and every publish's time. They can't give a title changed on the web, a deletion, or an Artifact published from Claude Desktop (Known gaps).
- **Codex** (slice 2): a rollout's `patch_apply_end` event carries `changes: {<path>: {type, content | move_path, unified_diff}}`, and `exec_command` calls carry `cmd`; 140 file changes in 120 days, 7 of them documents, 5 Share uploads. The source trait makes it one more `parse` implementation.

### Existence (Lookout's server, LIB-2.9)

- For each page of `outputs` the server answers, it stats the `file` rows' paths with the batched check VIEW-1.18 already has (`server/files.ts`, `checkPaths`: at most 100 paths, 2 s for the batch, `stat` only, nothing opened, no command). A page holds at most 50 rows, so one batch covers it. The answer is `exists` on Lookout's row, never stored: a file can come back (a Session rewrote it) or go between two refreshes.
- "Hide gone" is applied on the server after the stat, so a page can come back short or empty with more to follow: HIST-2.1's paging rules cover it (a short page fetches the next, at most 5 in a row, then "Load more").
- Evidence for "Hide gone" on by default: scratchpad documents last touched 0–3 days ago all existed (120 of 120), 4–7 days 28 of 60, older than 8 days 0 of 83; `output/` 45 of 45. A scratchpad file is the thing to open while it lives, and gone within a week, when the Artifact or Share made from it is the lasting item (32 of 52 Artifact source files were scratchpad files).
- tb-session reports no existence, by its boundary (LIB-4.7): `exists` would be a read of files on disk at answer time, the thing the boundary keeps out, and Lookout already has the check.

### Liveness and the Session button (LIB-2.2, LIB-3.5)

- A row's Session is live when its `session_id` is in the Session list Lookout already has (HIST-3.2's rule); its button is "Open", which selects it.
- Resume and Show go through History's resume route (`{sessionId, harness}`; the server re-reads the Session with `tb-session show`, so the directory never comes from the browser), with its answers `started`, `live` and `blocked` and its "Starting…" row (HIST-3.1, HIST Technical approach, Resume request). Nothing new is spawned here.
- A Session whose Transcript was deleted is `transcript_missing` in tb-session, and one removed by `index --prune` is absent from `show`; its Outputs stay (LIB-4.5) and the button is "Show" (HIST-3.3).

### Opening (LIB-3.3, LIB-3.4)

- A file that exists opens in VS Code through `vscode://file/<absolute path>` (VIEW-1.17), except `.html`, which VS Code would show as source. An `.html` opens in a new tab from a read-only route that serves only a path the last `outputs` answer listed for this server (an allowlist kept in memory, refreshed with each answer), as `text/html` with `Content-Security-Policy: sandbox allow-scripts`, so the page runs in an opaque origin and can't call Lookout's API or read its storage. Scripts run, so charts work; storage APIs such as `localStorage` don't, and that is accepted. The route reads the file as it is, follows no symlink outside the allowlist, serves nothing else, and runs no command. Chrome won't open `file://` from an `http` page, so a route is needed.
- An Artifact or Share opens its URL in a new tab with no referrer (VIEW-1.12). Lookout never fetches the URL.
- Copy link uses the clipboard as VIEW-1.14 does; the text is the URL, or the file's absolute path.

### Freshness (LIB-2.7)

- The tab reads `outputs` when opened and every 30 s while open, like Work's reads (WORK-8.1): a warm call is cheap (only a live Session's Transcript is stale), and `--after` keeps the incremental read small. The 20 s timeout, `LOOKOUT_TB_SESSION_BIN`, `PATH`, then `~/.local/bin` apply as for History.
- A tb-session without `outputs` fails the call with clap's usage error (exit 2), which Lookout shows as the install hint, the pattern HIST uses for 0.2.
- The list keeps its order while a row is expanded or the pointer rests on it (SIDE-3.4); pending moves apply once both end.

- **Design system:** the labelled button size (DS-7.1) and `RowActions` spacing (DS-7.4), both built; `Chip` for "gone" and "live"; a kind icon per row through lucide ([0008](../../decisions/0008-lucide-icons-only.md)).
- **World fakes:** a fake tb-session answering `outputs` beside `list`, `search` and `show`, and refusing it as 0.3.x does for the install hint.

### Known gaps

- **Moved files:** not tracked in slice 1; the old path goes gone, and the new one appears only once a Session Writes or Edits it. `cp`/`mv` into `output/` happened 78 times in 30 days (slice 3).
- **Files written by a shell heredoc:** not Outputs in slice 1 (218 such Bash calls in 30 days, mostly review notes in `/tmp`); an Edit of one later makes it an item (slice 3 for the obvious forms).
- **Artifacts changed on the web:** a title changed, an Artifact deleted, or one published from Claude Desktop or the web isn't seen; the row keeps the last publish's `title` and `version`.
- **Shares deleted or expired:** not seen until the Backyard reconcile (slice 2); the row shows what the upload printed.
- **Title of a file:** from the first Markdown heading or `<title>` in the Write's `content`, or the basename; an Edit never changes it.

### Key decisions

- **Mine the Transcripts, don't scan the disk**: every `Write`, Artifact publish and Share upload is in them with its path or URL and its Session; a disk scan has no Session link, no Artifacts or Shares, and the scratchpads are gone within a week.
- **The index lives in tb-session, not a standalone `tb-outputs` crate** (Dario, 2026-10-23): a standalone would parse the same bytes for the same reason (two parsers kept in step, or tb-session's parsers as an unversioned library, which no crate in the workspace does today), copy or join every Session fact the Library shows (titles, renames, project, headless, missing Transcript, resumable), split WORK's refs index (Gap 2, the same walk over tool blocks) and add a pin, a wrapper, a fake and a version for Lookout; the costs it would spare tb-session are measured and small (a full rebuild is 8 s, the tables are kilobytes beside a 113–237 MB index). Fleet reads tails and never tool results, and Lookout's own server is against 0005.
- **tb-session's boundary is written down, with one named exception** (correction to the draft, Dario, 2026-10-23): "facts from Transcripts; the git-owned check at index time is the one other input; nothing from the network, nothing from files at answer time". The draft had tb-session stat files for `exists` and run `git` for the include rule, both reads outside the Transcripts; the stat moves to Lookout, which already has the batched check (VIEW-1.18), and the git check stays because without it every repo file an agent writes would be indexed, and it runs once per directory at index time, never when answering.
- **Repo documents are out by the git rule** (Dario, 2026-10-23): a tracked `SPEC.md` or `knowledge/` file has a home, a PR and reviewers, and the `SPEC.html` Artifact is in anyway; reversible later with a per-path allowlist.
- **Scratchpad files are in while they exist, hidden once gone, "Hide gone" on by default** (Dario, 2026-10-23): 0 of 83 scratchpad documents older than 8 days still existed, and while they live they're the thing to open.
- **Kinds in slice 1 are file, Artifact and Share; Claude Docs in slice 2; PR bodies and gists out** (Dario, 2026-10-23): 4 Claude Doc creates in 30 days, 0 gists ever, and a PR is WORK's item.
- **Extensions: `md, html, htm, pdf` and images; `txt`, `json`, `csv` out** (Dario, 2026-10-23): 763 `.txt` and 124 `.json` writes in 30 days were scratch, and widening the list is one line.
- **Subagent Outputs are credited to the parent Session** (Dario, 2026-10-23), though tb-session must start reading `subagents/` and widen the change key: 478 of about 1,500 document writes happened in Subagents; without them a third of `output/` is missing.
- **Liveness is checked at read time, never stored as truth, and split by input** (Dario, 2026-10-23, amended by the correction above): files are Lookout's stat per page; Backyard's state is Lookout's join with `tb-backyard share list` (slice 2), since tb-session has no network and no PAT and Lookout already calls tb-pr with the same rules; nothing checks an Artifact.
- **A third right-sidebar tab with `L`, not a section inside History** (Dario, 2026-10-23): the Library is a list of items, not of Sessions, with its own filters; History's list stays a list of Sessions. HIST's Non-goals left the room ("PORTS can become one later").
- **Search in slice 1 is over title, path and URL, not content** (Dario, 2026-10-23): History already finds the Session that produced "the report about X", and content FTS needs a size cap and a Transcript-only source (slice 3).
- **Headless Sessions' Outputs follow History's headless toggle** (Dario, 2026-10-23): about 60 of the last 300 Sessions were headless eval runs, their reports are real Outputs, and the toggle already exists.
- **One item per key, with versions and "touched by", not a row per event**: 199 publishes went to 25 URLs, 46 of 540 document paths had 5+ edits and 20 were touched by more than one Session; a row per edit would be noise.
- **Gone items stay in the index**: tb-session never drops history (`transcript_missing` is the same pattern); the Session link of a gone report is how it's regenerated.
- **A click selects and expands; a button acts** (HIST-3.5, WORK-1.12): a stray click must never open a tab or resume a Session.
- **An `.html` opens from a sandboxed route, a `.md` in VS Code**: Chrome won't open `file://` from an `http` page, and an agent-written page must not run on Lookout's origin.
- **The `.html` route serves with `Content-Security-Policy: sandbox allow-scripts`; opening `.html` in VS Code is rejected** (Dario, 2026-10-23, "browser is the way to go"): scripts run so charts work, `localStorage` and the other storage APIs don't, and that is accepted; VS Code would show the source, not the report.
- **`index --prune` keeps a pruned Session's Outputs** (Dario, 2026-10-23): tb-session never drops history on its own; the item's `sessions` keeps the id and Lookout shows that Session's button as "Show" (read-only), as for `transcript_missing`.
- **Harness homes are only the roots tb-session's scanner already knows** (Dario, 2026-10-23): `CLAUDE_CONFIG_DIR` and `CODEX_HOME` set in a Session's environment aren't in the Transcript, so they aren't considered.
- **A Share uploaded without `--json` is anchored on its URL alone** (Dario, 2026-10-23): `title` and `visibility` are parsed from the printed text when it parses and left empty when it doesn't, so a change in tb-backyard's text costs fields, never the item.
