# Library

## Summary

One list of everything Sessions produced: the Markdown and HTML reports they wrote, the Artifacts they published on claude.ai and the Backyard Shares they uploaded. Each Output links back to the Session that made it, so it can be opened, copied, or regenerated by resuming that Session. The Library is a third tab in the right sidebar, beside History and Work. It reads tb-session's `events` command ([contract](../../contracts/tb-session-events.md)), which lists every recorded action as a fact: tb-session mines the Transcripts, Lookout's server decides what counts as an Output, groups the actions, titles the files and renders ([0010](../../decisions/0010-single-consumer-rules-stay-with-the-consumer.md)).

## Problem

A Session writes a report into `output/` or a scratchpad, publishes an Artifact, or uploads a Share, and a day later finding it again means remembering a path or a URL, or searching History for the Session and reading its chat. Artifacts have no list outside claude.ai's gallery, which doesn't say which Session published them. Scratchpad files are gone within a week, and by then the Artifact made from them is the only copy.

Measured over the last 30 days (2026-10-23): 143 Sessions wrote at least one document, 199 Artifact publishes went to 25 URLs, and 15 Shares were uploaded; a third of the `output/` documents were written by Subagents, whose Transcripts nothing lists today.

## Requirements

Slice 1 is what the criteria cover; slices 2 and 3 are under Later. Building blocks: tb-session 0.4.0 with its `events` command (the [contract](../../contracts/tb-session-events.md); released, Dependencies), and Fleet for live Sessions, as today. Lookout shows the Library tab with any tb-session; one without `events` (0.3.x) shows the install hint, as History does for 0.2.

### LIB-2 List what Sessions produced

An Output is a file, an Artifact or a Backyard Share that a Session, or one of its Subagents, produced. tb-session gives one row per recorded action (`write`, `edit`, `artifact`, `share`; contract E2, E3); which files count (LIB-2.10), one Output per kind and key with its Sessions (LIB-2.11) and a file's title (LIB-2.12) are Lookout's rules. A file also has a Type (`markdown`, `html`, `pdf`, `image`) from its extension, by LIB-2.10's table. An Artifact and the file it was published from are one row, the Artifact's (LIB-2.11).

- [x] LIB-2.1 Library lists Outputs newest `updated_at` first, grouped by day in the browser's local time ("Today", "Yesterday", then the date), 50 a page, more loading as you scroll. For page 1 and every re-read (LIB-2.7), Lookout's server reads every document event in one go: `tb-session events --all-projects --json --headless <the toggle> --limit 100000` twice in parallel, once for files with `--kind write,edit --ext <LIB-2.10's extensions>` and once with `--kind artifact,share` and no `--ext` (on Artifacts and Shares `--ext` filters by `source_path`, so it would drop a Share that has none), and `tb-session list --all-projects --json --limit 200`, page after page, for Session titles (LIB-2.6: one page of every Session printed 22 MB of first prompts, over the runner's 16 MB cap); if a call's `total_results` is larger than the rows it returned, it reads the next pages until all are in. It applies LIB-2.10 to LIB-2.12 and LIB-2.9 to the whole result and keeps it as the read the tab's later pages come from, so the pages of one scroll never mix two reads; a page 1 asked within 2 s of the last read, for the same headless value, reuses it. It answers 50 Outputs, the exact total after the filters (LIB-2.3) and whether more exist. A later page names the read it continues; a read the server no longer holds (it keeps the last 3) makes the tab read page 1 again, with no error. A page that doesn't fill the panel makes the tab fetch the next one itself until it does or nothing is left. Rows of a kind Lookout doesn't know are left out. (e2e)

(test)
- [x] LIB-2.9 Whether a file still exists is Lookout's server's answer, never tb-session's: for every file Output of the read, before any page is cut, the server stats its path and every Artifact's `source.path` with VIEW-1.18's batched check (at most 100 paths per batch, 2 s for the batch, a path still out then counts as gone), and its directory with the same limits (LIB-2.10). It reads no contents beyond LIB-2.12's title read and runs no command beyond LIB-2.10's git question. "Hide gone" hides the file Outputs whose directory exists and whose file doesn't; a file whose directory is gone was dropped already (LIB-2.10) and is never "gone". An Artifact row is never hidden because its source file is gone, and Artifacts' and Shares' URLs are never checked. Because it's checked for all of them first, the total, the "n gone Outputs are hidden" count and every page of 50 are exact. (e2e)
- [x] LIB-2.10 Which files are Outputs is Lookout's rule, applied to the file rows of `events` (an Artifact or a Share needs none of it). A file is an Output only when: its path is absolute and plain (VIEW-1.18; a `:` in it, known and accepted, is not); its extension, case-insensitively, is `md` (Type `markdown`), `html` or `htm` (`html`), `pdf` (`pdf`), or `png`, `jpg`, `jpeg`, `gif`, `svg` or `webp` (`image`); it is not under `~/.claude`, `~/.codex` or `~/.pi`; its directory still exists, a file whose directory is gone being dropped, not shown as gone; and it is not git-owned, meaning inside a git work tree and not ignored, which the server asks of `git`: the work tree root once per distinct directory, cached, and whether each path is ignored with one `git check-ignore --stdin` per root, since a `.gitignore` can ignore one file of a folder and not the next. Git is asked about physical paths (a symlinked folder is resolved first, and the answers are mapped back to the recorded paths). A folder or root git can't answer for (a timeout, a damaged index, a refusal such as "dubious ownership"; only git's "not a git repository" means no work tree) leaves out the file Outputs under it, as probably git-owned; the read never fails because of git, and the server logs one line per failing folder or root per read, a category and no path. (test)
- [x] LIB-2.11 Lookout groups the actions into Outputs. There is one Output per kind and key: a file's writes and edits are one file Output, an Artifact is its URL, a Share its token. Rows with the same `tool_use_id`, kind and key are one action (a forked Session repeats its copied actions, contract E6): it counts once and is credited to the Session with the earliest `created_at` in `tb-session list`, else the smaller `session_id`; rows without a `tool_use_id` count as they are. An Output has the time of its first and last action, its count of actions, and every Session that touched it, each once, newest last touch first, with its last touch word: `write` or `edit`, `publish` for an Artifact, `upload` for a Share. A file Output whose path is an Artifact's `source_path` is not a row of its own: it rides on the Artifact as `source` (path, Type, first and last write or edit, count), and its Session touches count for the Artifact's Sessions. A file that is the source of two Artifacts rides on both; a file edited after the Artifact's last publish stays folded, and its `source` is then newer than the Artifact's `updated_at`. (test)
- [x] LIB-2.12 A file Output's title is, for a Markdown file, its first level-1 ATX heading (`# …`), skipping YAML front matter and fenced code, and for an HTML file its `<title>`, read by the server from the first 8 KB of the file and cached by path, mtime and size; a file with neither, and a PDF or an image, has its basename. An Artifact's and a Share's title is the newest action's, as the tool printed it. The search (LIB-2.4) matches this title. A file that doesn't exist is not read. (test)

## Non-goals

- Codex and Pi sources, Claude Docs, gists, PR bodies and comments, Slack canvases, screenshots: PRs are WORK's items (175 creates and 237 body edits in 30 days would bury the documents); Claude Docs and Codex come in slice 2 (Later); the rest until one is missed.
- Repo documents: a tracked `SPEC.md`, `knowledge/` or `docs/` file has a home, a PR and reviewers; its published `SPEC.html` Artifact is in anyway.
- Code, `.txt`, `.json`, `.csv` and `.jsonl` files: in 30 days they were scratch (763 `.txt` writes, 124 `.json`). `events` records them all; widening the extension list is a one-line change in LIB-2.10's table and in the row icons.
- Content search, an in-app preview, moved-file (`cp`/`mv`) and heredoc tracking: slice 3.
- Backyard reconciliation (state, expiry, views, deletion) and Artifact reconciliation with claude.ai: slice 2 and 3; in slice 1 a Share's `visibility`, `state` and `expires_at` are what its upload printed.
- Deleting, renaming, tagging or moving Outputs; uploading, publishing or regenerating anything from Lookout. Resuming the Session is how an Output is regenerated.
- Reading a file's contents in Lookout to index, preview or search it: the server reads the first 8 KB of a Markdown or HTML file for its title (LIB-2.12) and nothing else; the Open route streams a listed file to a tab as it is.
- Serving a page's sibling files (`./chart.js`, `./style.css`): the route serves the listed file alone (Known gaps).
- Dropping Outputs from tb-session: its history is never dropped automatically (`transcript_missing`, `pruned`, contract E7); the Session link of a gone report is how you get it back. Lookout itself drops a file whose directory is gone (LIB-2.10).
- Other Hosts.

## Technical approach

### Source ([0010](../../decisions/0010-single-consumer-rules-stay-with-the-consumer.md), [0005](../../decisions/0005-building-blocks-live-outside-lookout.md), [contract](../../contracts/tb-session-events.md))

- **Command:** `tb-session events --all-projects --json` (contract E1), twice and in parallel: `--kind write,edit --ext md,html,htm,pdf,png,jpg,jpeg,gif,svg,webp` for files, and `--kind artifact,share` **without** `--ext` for the rest, each with `--headless <the toggle>` and `--limit 100000`. On a write or edit `--ext` matches the file's extension; on an Artifact or a Share it matches the recorded `source_path`, so one call with `--ext` would drop the Share with no source (1 of 21 real Shares here), and one without it would read every code and text write (9,098 rows in the PR's own measurement). Alongside, `tb-session list --all-projects --json --limit 100000` for Session titles. If `total_results` is larger than the rows a call returned, the server reads the next pages (`--page`) until it has them all; it never answers from a partial read.
- **What the rows are** (contract E2 to E6): one row per recorded action, `kind` `write`, `edit`, `artifact` or `share`, newest first, with `key`, `timestamp`, `title` (a file's basename; an Artifact's or Share's from the tool result), `path` and `ext` for files, `url`, `source_path`, `version`, `seq`, `visibility`, `state`, `expires_at`, the Session (`session_id` is the parent's, `subagent` the Transcript file or null), `project_path`, `git_branch`, `headless`, `transcript_missing`, `pruned` and `tool_use_id`. `events` applies no extension, git, Harness-home or fold rule, has no Session title, and `total_results` counts actions. What Lookout does with the rows is below and in LIB-2.9 to LIB-2.12; the boundary is [0010](../../decisions/0010-single-consumer-rules-stay-with-the-consumer.md) and contract E11.
- **The rules, in order:** (1) keep file rows whose path is absolute and plain; (2) drop paths under the Harness homes (`~/.claude`, `~/.codex`, `~/.pi`; 42 of 1,319 file keys here); (3) group (LIB-2.11) and fold Artifact sources; (4) drop a file Output whose directory no longer exists, and one that is git-owned; (5) stat the rest (LIB-2.9) and read titles (LIB-2.12). A source file that rides on an Artifact stays with it in step 3 even if its directory is gone, so the Artifact keeps "newer than published" and its source path; a directory that is gone can't be asked about git, so for that fold it counts as not git-owned. Only a file that passes steps 1 to 4 on its own is an Output row.
- **Subagents:** a Subagent's Transcript is read by tb-session (`subagents/agent-*.jsonl`) and its rows carry the parent's `session_id` with `subagent` set, so crediting the parent needs nothing from Lookout. Measured 2026-10-29: 1,393 of 3,066 rows came from Subagents.
- **Session titles:** `events` has none. The server joins the rows' `(harness, session_id)` to `list` for `summary`, else `first_prompt`, and `created_at` for LIB-2.11's fork rule; a Session not in `list` (pruned, or no user prompt) keeps the id's first 8 characters. 2,398 Sessions here, 0.75 s.
- **Artifacts have no list but the Transcripts:** the Artifact tool's `list` works only from inside a Session, gives no Session or creation time, and there's no CLI or public API (the `claude` binary talks to an MCP endpoint behind claude.ai's session auth). The Transcripts give `artifact_id`, `url`, `title`, `version`, `seq` and every publish's time; `events` rows carry them. They can't give a title changed on the web, a deletion, or an Artifact published from Claude Desktop (Known gaps). 95 of 182 publishes had their file Written or Edited in the same Session; the rest came from a heredoc, an earlier Session or a Subagent, and have `source_path` but no file Output to fold.
- **Codex** (slice 2): `events` indexes Claude Code Transcripts only. A rollout's `patch_apply_end` event carries `changes: {<path>: {type, content | move_path, unified_diff}}`, and `exec_command` calls carry `cmd`; 140 file changes in 120 days, 7 of them documents, 5 Share uploads. It would be a tb-session change first, then rows like the others.

### The read, paging and existence (Lookout's server, LIB-2.1, LIB-2.9 to LIB-2.12)

- **Why everything is read, then paged in Lookout:** an Output's actions span the whole history, a first write on an old page and a last edit on page 1. Paging `events` gives an Output a partial Session list, wrong first and last dates and counts, and an Artifact and its source file on different pages can't fold. So for page 1 and every re-read the server reads all the document events at once and groups them itself. Measured on Dario's Mac 2026-10-29 (0.4.0, warm): `events --all-projects --json --headless exclude --kind write,edit,artifact,share --ext <the table> --limit 100000` took 0.12 s and returned 2.3 MB: 3,066 rows, 1,535 distinct keys, from 185 Sessions, 1,393 rows from Subagents; `list` 0.75 s. That replaces the five-tb-session-pages loop, the continuation snapshots (the 409) and the "Load more" fallback, which existed only because tb-session paged.
- **Paging is the panel's:** the server holds the last 3 reads (the filtered, grouped Outputs with their stats and titles; a few hundred KB each) and cuts 50 rows from the one a request names. Page 1 reads, or reuses a read under 2 s old for the same headless value, so typing in the filter doesn't re-read per keystroke; filters and the text search run on the read's Outputs, never in tb-session. The answer carries the read's name, 50 rows, the exact total after the filters and whether more exist. A request for a read the server no longer holds is answered as "read again", and the tab asks for page 1; a refresh (LIB-2.7) replaces the loaded rows with as many from the new read.
- **The stat:** VIEW-1.18's batched check (`server/files.ts`, `checkPaths`: at most 100 paths, 2 s for the batch, `stat` only, nothing opened, no command) over the file Outputs' paths and the Artifacts' `source.path`s, run for all of them before paging (1,319 file keys here, 14 batches, milliseconds). The check answers "is a file"; the directory check is the same limits with a directory answer, over the distinct directories (510 among 1,319 file keys). The answer is `exists` on Lookout's row, kept only in the read: a file can come back (a Session rewrote it) or go between two refreshes.
- **Git-owned:** the server asks `git` read-only, through an allowlisted argv, only about directories that exist, by their physical path (`realpath`; git refuses a path beyond a symbolic link) and maps answers back to the recorded paths: the work tree root of a directory (`git -C <dir> rev-parse --show-toplevel`, cached per directory, 10 minutes; only the answer "not a git repository" is cached as no work tree, a failure is never cached) and, for paths inside a root, whether each is ignored (`git check-ignore --stdin`, one run per root). Inside a work tree and not ignored is git-owned, so the file is not an Output; ignored (an `output/` folder in `.gitignore`) or outside any work tree is. A tracked file in an ignored folder is not ignored (no `--no-index`), so it is git-owned. At most 8 runs at once. The first read asks for up to 510 directories, batched per repo root; later reads hit the cache. Git runs in the C locale (`LC_ALL=C`, `LANGUAGE` empty) so its diagnostics are matched in English, and "not a git repository" is recognized only as the diagnostic that starts a line. Several recorded folders with one physical folder share one discovery per read (one git call, one log line). Canonicalizing a folder has the same 2 s limit, and a `realpath` timeout or error counts as a git failure. A failure (timeout, damaged index, dubious ownership, any other git error) leaves out the file Outputs of that folder or root, since a file inside a work tree is probably git-owned, and never fails the read: Artifacts, Shares and other files are answered. Each failure logs one line per read (`lookout: library: git could not answer for a folder|root, its files are left out: <category>`), with the category (timed out, dubious ownership, damaged index, exit code) and never a path or git's own text.
- **Titles:** the first 8 KB of an existing `.md`, `.html` or `.htm` file (for HTML, with comments and `<script>`/`<style>` content skipped while scanning outside the `<title>` element; the title's own text is kept as written), cached by path, mtime and size (the stat already has both); entries for paths no longer in a read are dropped after an hour. Nothing else of a file is read.
- **Hide gone, with the folder rule** (changes the 2026-10-23 evidence): scratchpad documents last touched 0–3 days ago all existed (120 of 120), 4–7 days 28 of 60, older than 8 days 0 of 83, and their folders are cleared with them. Such a file is now dropped with its folder and never shown as gone; "Hide gone" covers files deleted from folders that still exist. While a scratchpad file lives it's the thing to open; once it's cleared, the Artifact or Share made from it is the lasting item (32 of 52 Artifact source files were scratchpad files).
- **The repo select** is built from every `project_path` of the last read plus the chosen one.
- tb-session reports no existence, no git state and no title from a file, by its boundary (contract E11): each would be a read of files on disk at answer time, which `events` doesn't do.

### Liveness and the Session chips (LIB-2.2, LIB-3.5)

- A row is live when any of its Sessions' ids is in the Session list Lookout already has (HIST-3.2's rule); that chip is "Open", which selects it.
- The chip's Harness, `project_path`, `headless` and `transcript_missing` come from the Output's action rows (contract E2) and its title from `list` (LIB-2.6), so no `show` is needed on expand; Lookout's `withBlock` then applies as in History.
- Resume and Show go through History's resume route (`{sessionId, harness}`; the server re-reads the Session with `tb-session show`, so the directory never comes from the browser), with its answers `started`, `live` and `blocked` and its "Starting…" row (HIST-3.1, HIST Technical approach, Resume request). Nothing new is spawned here.
- A Session whose Transcript was deleted is `transcript_missing` in its rows and still answers `show`: its chip is "Show" (HIST-3.3). One removed by `index --prune` is `pruned: true` in its rows and `session_not_found` in `show`, so its chip is text (LIB-2.6).

### Opening (LIB-3.3, LIB-3.4)

- A `.md` that exists opens in VS Code through `vscode://file/<absolute path>` (VIEW-1.17), where its source is what you'd edit. Everything else a browser renders natively opens in a new tab from a read-only route: `.html` and `.htm` as `text/html`, `.pdf` as `application/pdf`, images with their type (an SVG can carry scripts, so it gets the same sandbox). Chrome won't open `file://` from an `http` page, so a route is needed.
- The route answers with `Content-Security-Policy: sandbox allow-scripts allow-popups allow-popups-to-escape-sandbox` and `X-Content-Type-Options: nosniff` on every answer, errors included. `allow-scripts`: charts work; storage APIs such as `localStorage` don't, accepted. No `allow-same-origin`: the page is an opaque origin, its `fetch` to Lookout carries `Origin: null`, which `server/security.ts` refuses (403). `allow-popups` with `allow-popups-to-escape-sandbox`: links in a report (PRs, Backyard, Grafana) open as ordinary tabs of their own origin, not sandboxed and half-broken; a popup aimed at Lookout's origin is a plain GET, carries no token, can't call a mutation, and the page can't read it back (cross-origin).
- **The allowlist:** every file path the server's reads listed since it started (file Outputs' paths and `source.path`s), bounded at 10,000 with the oldest out, compared as the exact normalized string: nothing is joined to a root, so no traversal is possible. The leaf must be a regular file by `lstat` (no symlink at the leaf; a symlinked parent such as `/private/tmp` is fine) and its extension one the route serves. The route reads the file as it is, serves nothing else (no sibling files, Known gaps) and runs no command.
- An Artifact or Share opens its URL in a new tab with no referrer (VIEW-1.12). Lookout never fetches the URL.
- Copy link uses the clipboard as VIEW-1.14 does; the text is the URL, or the file's absolute path.

### Freshness (LIB-2.7, LIB-2.8)

- The tab reads when opened, within 10 s after Fleet's list changes (the moment an Output is likely new: a Session ended, a Subagent finished; Lookout reads Fleet's list every 2 s), and every 60 s while the tab is visible. A read is two `events` calls and one `list` (0.12 s and 0.75 s warm, in parallel) plus the stats, so a refresh costs about a second; a call that re-parses a changed live Transcript costs that parse (1.57 s for 30 MB), which is why 30 s was rejected, and tb-session keys each Subagent Transcript separately.
- A refresh is a page 1: it reads everything, replaces the loaded rows with the same number from the new read and applies pending moves once no row is expanded and the pointer rests elsewhere. No `--after` delta: an Edit moves an Output from deep in the list to the top, and the read is cheap.
- The 20 s timeout, `LOOKOUT_TB_SESSION_BIN`, `PATH`, then `~/.local/bin` apply as for History, except the first call after an upgrade: a schema bump re-parses every Transcript on first use (contract E8; 16.7 s measured for v3 to v4 here, 18.9 s in the PR), and that same call hits History and Work, so the Library waits 60 s with "Indexing Transcripts…" rather than answering a 504 on upgrade day; past 60 s the Alert names `tb-session index --all-projects`.
- A tb-session without `events` (0.3.x) fails the call with clap's usage error on stderr, `error: unrecognized subcommand 'events'`, exit 2 (contract E10), which Lookout shows as the install hint. `server/history.ts` matches only `unexpected argument '--…'` for its `legacy` flag, so the Library matches its own line and keeps its own flag. A 0.3.x run after 0.4.0 has upgraded the index fails with "the index was written by a newer tb-session" (E8), a failed read like any other.
- The list keeps its order while a row is expanded or the pointer rests on it (SIDE-3.4); pending moves apply once both end.

### Known gaps

- **Moved files:** not tracked in slice 1; the old path goes gone, and the new one appears only once a Session Writes or Edits it. `cp`/`mv` into `output/` happened 78 times in 30 days (slice 3).
- **Files written by a shell heredoc:** not Outputs in slice 1 (`events` infers no shell writes; 218 such Bash calls in 30 days, mostly review notes in `/tmp`); an Edit of one later makes it an Output (slice 3 for the obvious forms). An Artifact published from such a file has `source_path` but no folded `source`.
- **Scratchpad files whose folder was cleared are dropped**, not listed as gone: Lookout can't ask git about a folder that no longer exists, and the Artifact or Share made from the file is the lasting item. The Session link is gone with it for a file that has no Artifact or Share.
- **A relative path** (a Write the Transcript recorded without an absolute path, or a relative `source_path`) isn't an Output and doesn't fold; Lookout has no working directory to resolve it against.
- **A cached git answer** lives 10 minutes: a `git init` or a `.gitignore` edit takes that long to show.
- **A page's sibling files:** a report that references `./chart.js` or `./style.css` breaks in the route, which serves the listed file alone; brand Artifacts inline everything, and multi-file pages are what the Artifact tool's `files` is for.
- **Artifacts changed on the web:** a title changed, an Artifact deleted, or one published from Claude Desktop or the web isn't seen; the row keeps the last publish's `title` and `version`.
- **Shares deleted or expired:** not seen until the Backyard reconcile (slice 2); the row shows what the upload printed.
- **Title of a file:** the first Markdown heading or `<title>` in the first 8 KB of the file as it is now (LIB-2.12), so an edit changes it; a heading further down, or a `<title>` built by script, isn't found and the basename shows.
- **A fork whose original is out of `list`:** the fork rule (LIB-2.11) ranks a Session `list` doesn't have after one it does, so a pruned original's copied actions are credited to the fork.
- **Codex and Pi** Sessions produce no `events` rows; tb-session indexes Claude Code Transcripts for them (slice 2).
- **A folded Markdown source:** an Artifact published from a `.md` (a skill may ask for one) folds that file under the Artifact, so the Markdown chip alone doesn't list it; Pages does.

### Key decisions

- **Mine the Transcripts, don't scan the disk**: every `Write`, Artifact publish and Share upload is in them with its path or URL and its Session; a disk scan has no Session link, no Artifacts or Shares, and the scratchpads are gone within a week.
- **The index lives in tb-session, not a standalone `tb-outputs` crate** (Dario, 2026-10-23): a standalone would parse the same bytes for the same reason (two parsers kept in step, or tb-session's parsers as an unversioned library, which no crate in the workspace does today), copy or join every Session fact the Library shows (titles, renames, project, headless, missing Transcript, resumable), split WORK's refs index (Gap 2, the same walk over tool blocks) and add a pin, a wrapper, a fake and a version for Lookout; the costs it would spare tb-session are measured and small (a full rebuild is 8 s, the tables are kilobytes beside a 113–237 MB index). Fleet reads tails and never tool results, and Lookout's own server is against 0005. Amended 2026-10-29: the index still lives in tb-session, but as `events` facts; the Library's rules (include rule, fold, titles) moved to Lookout ([0010](../../decisions/0010-single-consumer-rules-stay-with-the-consumer.md)).
- **tb-session's boundary is written down, with one named exception** (correction to the draft, Dario, 2026-10-23): "facts from Transcripts; the git-owned check at index time is the one other input; nothing from the network, nothing from files at answer time". The draft had tb-session stat files for `exists` and run `git` for the include rule, both reads outside the Transcripts; the stat moves to Lookout, which already has the batched check (VIEW-1.18), and the git check stays because without it every repo file an agent writes would be indexed, and it runs once per directory at index time, never when answering. Superseded 2026-10-29: the git-owned check is no longer tb-session's. tb-session's boundary is "facts from Transcripts, nothing else" with no exception (contract E11); Lookout asks git per directory.
- **The tb-session contract is a file, not criteria** (grill, 2026-10-23): `pnpm req-check` reads Vitest's and Playwright's listings, never Rust tests in another repo, and a Lookout test named after a tb-session point would prove the fake, not tb-session; HIST and WORK hold their Building-block gaps under Technical approach too. `docs/contracts/tb-session-outputs.md` is what the cli-toolbox PR implements and tests against. - **One row of Type chips, Pages = HTML files + Artifacts** (Dario, 2026-10-23, changed from the grill's six): what Dario narrows to is "the pages", and an HTML file and an Artifact are the same thing to open, a page in a browser tab, often the same page before and after publishing; one chip for both means the fold (below) never has to decide which chip a row belongs to. Multi-select with ⌥-click for "only this", remembered, so the daily view is a one-time setup, not a preset; tb-session owns `type` and `--type` because it already owns the extension rule, and a flag keeps paging exact where filtering after the fact would make pages short. The grill's reasons against folding were about which chip a folded row belongs to; with HTML files and Artifacts on one chip that question is gone. The fold is tb-session's so paging stays exact; the file is reachable through the Artifact's row (its path, "Open file", "newer than published"), nests under two Artifacts when it's the source of both, and its going never hides the Artifact. Amended 2026-10-29: the fold is Lookout's (LIB-2.11); with everything read at once, paging stays exact anyway.

Amended 2026-10-29: `events` records the Share from the tool result; fields it can't parse are left out.
- **Read everything, page in Lookout** (Dario, 2026-10-29): an Output's actions span the whole history (first write on an old page, last edit on page 1), so paging `events` gives partial Session lists, wrong dates and counts, and an Artifact and its source file on different pages can't fold. Cost measured on Dario's Mac 2026-10-29 (0.4.0, warm): the all-document call took 0.12 s, 2.3 MB, 3,066 rows, 1,535 distinct keys, 185 Sessions (1,393 rows from Subagents). It replaces the five-page loop, the continuation snapshots (the 409) and the "Load more" fallback, which existed only because tb-session paged; the panel's own paging (50 rows, more on scroll) stays, and `total` is exact again.
- **Title from the first heading** (Dario, 2026-10-29): a Markdown file's title is its first `# ` heading and an HTML file's its `<title>`, read from the first 8 KB, cached by path, mtime and size, else the basename; PDFs and images keep the basename. With everything read, Lookout searches its own list (title, path, URL, source path) instead of passing `--q`, so the search matches this title too. It reverses "a file's title comes from the Write's content" (2026-10-23), which tb-session no longer extracts.
- **Drop files whose folder is gone** (Dario, 2026-10-29): git-owned files are not Outputs as before, but Lookout decides it now (inside a work tree and not ignored, asked once per directory and cached; 510 distinct directories among 1,319 file keys). A directory that no longer exists can't be asked, so its files are dropped, not shown as gone. This changes the 2026-10-23 decision "scratchpad files are in while they exist and hidden once gone": a scratchpad report is dropped once its folder is cleared, and "Hide gone" covers only files deleted from folders that still exist.
- **The Library's rules are Lookout's** (Dario, 2026-10-29, after the cli-toolbox PR #106 review; [0010](../../decisions/0010-single-consumer-rules-stay-with-the-consumer.md)): tb-session gives facts (`events`), and the extension table, Harness homes, git-owned check, one Output per key, fold and titles are a single consumer's rules, so they live in Lookout's server. The old contract's C3 to C6 became LIB-2.10 to LIB-2.12.
- **Two `events` calls, `--ext` on the file call only** (2026-10-29, from measuring): on an Artifact or a Share `--ext` filters by `source_path`, which drops a Share with no source (1 of 21 real Shares here); the file call carries the table, the other `--kind artifact,share` without it.
- **A forked Session's copied actions count once, for the earliest-created Session** (chosen 2026-10-29 while amending, confirmed by Dario 2026-10-30): rows with one `tool_use_id`, kind and key are one action; credit goes to the Session with the earliest `created_at` in `list`, else the smaller `session_id`. A fork is created after the Session it copies, so the earliest-created did the work, and unlike the row `id` the rule survives an index rebuild or a different scan order. Rows without a `tool_use_id` count as they are.
- **Session titles from `list`** (Dario, 2026-10-29): `events` has no Session title, so the server reads `tb-session list --all-projects --json --limit 200`, page after page, beside it (13 pages, 0.73 s and 3.8 MB at most a page for 2,406 Sessions here; one page of all of them was 22 MB of first prompts, over the runner's 16 MB cap); a Session not in it keeps the id's first 8 characters.
