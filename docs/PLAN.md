A colleague's `res` is a per-machine queue for heavy jobs on macOS: `res run --prio live|check|bg [--workers N] [--mb N] -- <cmd>` waits until the job's estimated cores and memory fit the measured free budget (2 cores and 4 GB never leased), by priority with ageing then first come, and holds a lease that follows the job's real use every 5 s; it injects `--maxWorkers`/`--workers`, `NODE_OPTIONS=--max-old-space-size` and a `taskpolicy` QoS. A PreToolUse hook, `res-guard.mjs`, denies a known heavy command (vitest, Playwright, tsc, typecheck, installs, builds, `npm test`) run outside `res`, with the corrected command. The source is now in a second artifact (https://claude.ai/artifact/YEZAsvURXinXJ3nGSCC7Vi: `res.mjs` 1,280 lines, `res-guard.mjs`, 28 tests, README; Node only, no dependencies, no network; it writes only under `~/.cache/res`). It settles what parking the item left as guesses:
    - `res status --json` is `{machine, load1, psCores, availMB, freePct, budget: {…, usage: {<entry id>: {cores, mb}}}, entries}`.
    - An entry is `{id, pid, session, cwd, command, cls, tool, kind: run|standing, prio, state: waiting|holding, workers, cores, mb, idle, req, queuedAt, waitingSince, since, peakMB, peakCores}`.
    - `session` is the tmux session name when `$TMUX` is set (`tmux display -t $TMUX_PANE -p '#S'`), else `$CLAUDE_CODE_SESSION_ID`: for a Lookout Session, which runs in its own tmux session (0001), that is its Session host's name, so a waiter maps to its Session without walking process trees.
    - `metrics.jsonl` holds one line per run, hold, release and hook denial; `res report --since` summarises it.
